# 可用性测试材料（E03）

对应规划：E03「进行目标用户可用性测试并修正主流程」、12.6「至少完成一轮目标多人场景测试」。
**这份材料是给执行人用的**：准备 10 分钟、测试 15 分钟、记录 5 分钟。

> 当前状态：材料已就绪，**测试尚未执行**（需要真实 3—4 人参与）。执行后把结果填回本文第六节，并在 `测试报告.md` 把 E03 从「⚠️ 未做」改成结论。

## 一、要验证的三个假设

| # | 假设 | 如果被推翻，要改什么 |
|---|---|---|
| H1 | 成员在自己手机上填「必须要/最好有/不要」比在群里被问更快 | 第 2 步的填写粒度或话术要重设计 |
| H2 | 「取舍说明」能让人理解为什么推荐这套，而不是只盯总价 | 解释层（`explain.py`）要重写优先级 |
| H3 | 票根会被愿意发到群里（传播意图） | 票根的字段选择/视觉要调整 |

## 二、参与者与场景

- **1 组 3—4 人**，最好本来就是会一起点麦当劳的同事/室友/朋友。
- 其中 1 人当「发起人」（操作电脑/手机），其余当「成员」（只填自己的心愿）。
- **真实场景**：就说「你们现在真的要点一顿麦当劳，用它试试」，费用自理（本作品不代下单）。
- 不要让参与者提前看 README 或演示脚本。

| 项 | 说明 |

## 四、任务脚本（照着念，不要提示操作）

**开场（30 秒）**
> 「这是一个帮一群人点麦当劳的小工具。你们现在要点一顿，试着用它把这顿饭定下来。我在旁边记录，遇到不会的地方就按你自己的想法试，不用问我。」

**任务 1｜发起（主持人操作）**
> 「建一次聚餐：4 个人，预算 200，就选你们常去的那家店。」

记录：是否找到「查门店」→ 是否理解「共同预算」是谁的钱。

**任务 2｜成员填心愿（每人 60 秒，自己填）**
> 「每个人说一下：必须要什么、最好有什么、绝对不要什么。」

记录：**每个人填了几条**、有没有人问「必须要和最好有什么区别」、有没有人跳过「不要」。

**任务 3｜看方案（2 分钟）**
> 「看看这三套，你觉得哪套是给你们的？为什么？」

记录：先看价格还是先看心愿；能否说出「哪套满足了我的必须」；有没有人误以为已经下单了。

**任务 4｜确认（1 分钟）**
> 「就选这套吧。」

记录：是否会找「确认」在哪；看到「未下单、未支付」的提示后是否仍然困惑。

**任务 5｜票根（1 分钟）**
> 「如果要把这个发到群里，你会改什么？」

记录：是否主动改昵称/关字段；有没有人试图上传照片；**是否愿意真发**（H3）。

**结束访谈（2 分钟，3 个问题）**
1. 刚才哪一步最烦？为什么？
2. 如果只能用一句话跟别人介绍它，你会怎么说？
3. 你会真的在下次聚餐时用它吗？不会的话，缺什么？

## 六、判定标准

| 假设 | 通过 | 不通过 |
|---|---|---|
| H1 填写更快 | 4 人全部独立填完，平均 < 60 秒/人，且无人问「必须要/最好有区别」超过 1 次 | 有人填不完，或需要主持人代填 |
| H2 解释可理解 | ≥3 人能说出「哪套满足了我的必须」+「为什么贵/便宜」 | 多数人只复述总价 |
| H3 有传播意图 | ≥2 人愿意发到群里（改昵称/关字段也算愿意） | 无人愿意发，或都觉得「没必要」 |

**通过后**：把结论与关键原话填进 `测试报告.md` 的 12.6 表格，E03 改为「✅ 已完成（N 人）」。
**不通过**：在 `测试报告.md` 记一条缺陷，说明改哪一层（流程 / 文案 / 视觉），再跑一轮。

## 八、隐私与合规

- 不录人脸、不录声音；只记操作与用时。
- 参与者昵称可用化名；票根截图需打码昵称后再进交付材料。
- 参与者可随时中止，已产生的本地数据可用「设置 → 清除本地数据」删除。
- 本作品**不会**替参与者下单或支付，测试中的消费由参与者自己在麦当劳 App 完成。
