## 一、P0（破坏核心承诺）— 3 条全部确认

### P0-1 分账金额重复计数 ✅ 确认

- **复现**（现在会失败的旧行为）：
  ```
  items: X×1(m1) 2500, Y×1(m1) 1000, X×1(m2) 2500；官方总价 6000
  旧 item_gross → [5000, 1000, 5000]，旧分账 → m1=3273 / m2=2727
  ```
- **根因**：`allocate.item_gross` 先按 `productCode` 把官方 `subtotal` 聚合成一个数，随后给**每一行**都赋这个聚合值。同码多行（两位成员各点一份同款）时被计了 N 倍。
- **修复**（`app/allocate.py:41`）：改为「按码聚合 → 按各行数量占比拆回 → 最后一行取剩余差额」。这样无论官方返回「按码合并一行」还是「逐行明细」，拆分结果之和都恰好等于官方小计。
- **验证**：
  - `test_regressions.TestP0Allocation`（4 条）：聚合形态 / 逐行形态 / 分账结果 / 1:2:4 不均拆分仍等额；
  - 真实链路复跑场景 C4（8 人，3 人同点麦辣鸡腿堡、2 人同点巨无霸）：三套方案 `Σ应付 == 整单`，且同款每人只计一份（2250×3，不是 6750×3）。

### P0-2 「不要」硬约束漏判 ✅ 确认

- **复现**：`expand_never(['辣的'])` 返回 `['辣的']`，对「麦辣鸡腿堡」不命中；`微辣`、`不吃辣`、`不吃牛肉`、`芝士奶酪` 同样漏判。
- **根因**：`expand_never` 用整词等值匹配词表，任何口语变体都落到 unknown 分支按原文做子串匹配，而商品名里没有「辣的」。
- **修复**（`app/rules.py`）：新增 `_strip_never_affixes`（剥掉「不吃/不要/别放/忌」前缀与「的/类/味/制品」后缀，最多 3 层），并把匹配改为三段式：**整词等值 → 组名双向包含 → 组内词双向包含 → 原文兜底**。
- **验证**：`TestP0NeverVariants`（5 条）覆盖 辣/辣的/微辣/不吃辣/不要辣/别放辣椒/麻辣的、牛肉各变体、芝士奶酪、以及「不能被误判」的反例（不吃牛肉不影响麦辣鸡腿堡）。

### P0-3 失败结果被写入缓存 ✅ 确认

- **复现**：`_cached` 不区分成败，loader 返回 `{"ok": false, "error": NETWORK}` 也按 180s/300s 存。
- **根因**：缓存条目 TTL 只由调用方传入，没有「失败短挡」的概念。
- **修复**（`app/server.py`）：缓存值改为 `(存入时刻, 本条TTL, 值)`；成功用完整 TTL，失败只挡 `FAIL_TTL = 5s`。
- **验证**：`TestP0FailureCache`（3 条）：失败条目 TTL 必须等于 `FAIL_TTL` 且 < 10s、成功条目等于完整 TTL、5 秒后重新穿透 loader 能拿到成功结果。
- **用户体验变化**：网络抖一下不再让「菜单查询失败」定格 3—5 分钟，重试按钮 5 秒后就真的会重试。

## 五、下一轮建议（按性价比排序）

1. **HTTP 层与并发的自动化用例**（当前 P2-2/2-5/2-6/2-4 靠手工 curl 验证）：起一个临时 `ThreadingHTTPServer` 在本进程内跑断言，可覆盖方法表、状态码、并发写。
2. **§四 未做项里的 2 与 5**：路由方法表 + 访问日志开关，属工程整洁度。
3. **`_finalize` 拆分**：等演示结束、有时间窗口再做，用现有 64 项测试当安全网。
4. **金额链路的状态机校验**：为「核价快照」加 `quotedAt + planHash`，前端校验「展示的方案与核价结果同源」，进一步防旧价复用。
