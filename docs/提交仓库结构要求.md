## 一、必须文件清单（共 5 项，均不可改文件名）

以下依据 `activityGuidelines.md`「开发与发布项目」章节原文：「参赛项目应包含至少以下文件，且以标准格式命名」。

| # | 文件 | 内容要求 | 文件名 | 文件内容 |
|---|------|---------|--------|---------|
| 1 | `README.md` | 项目介绍、安装方法、使用示例、目标用户 | ❌ 不可改 | 可自行撰写 |
| 2 | `CONTEST_DECLARATION.md` | 参赛声明：原创性、合规性、敏感信息声明（防止项目被直接盗用） | ❌ 不可改 | ❌ **不可改动，必须逐字使用官方原文** |
| 3 | `MCP_INTEGRATION.md` | 说明实际使用的麦当劳 MCP Server、Tool、调用流程和业务价值 | ❌ 不可改 | 可自行撰写 |
| 4 | `mcp-config.example.json` | 脱敏后的 MCP 配置示例，**只允许环境变量占位符** | ❌ 不可改 | 可自行撰写 |
| 5 | 源代码 | 项目主体代码或可运行内容 | — | 形式不限 |

> ⚠️ **两处规则表述不一致，以完整规则为准**：README 主页的文件表格未列出 `mcp-config.example.json`，但完整规则 `activityGuidelines.md` 明确将其列为必须文件。README 自己也声明「排名规则、赛事奖励及注意事项等，请参见 activityGuidelines.md」。**结论：按 5 项必须文件准备。**

### 各文件要点

**1. README.md** — 四要素缺一不可：项目介绍、安装方法、使用示例、目标用户。

**2. CONTEST_DECLARATION.md** — 唯一「内容也不可改」的文件。官方原文含五节：原创性声明 / 合规声明 / 信息安全声明 / 使用提示 / 规则遵守声明。建议直接 `curl` 官方仓库文件放入项目根目录，不要手打。

**3. MCP_INTEGRATION.md** — 需覆盖四要素：用了哪个 MCP Server、具体 Tool 清单、调用流程、业务价值。本项目可基于 `docs/MCP能力矩阵.md` 与 `docs/MCP联调记录.md` 提炼。

**4. mcp-config.example.json** — 脱敏配置示例，与 CONTEST_DECLARATION 的信息安全声明联动：**只允许环境变量占位符，禁止出现任何真实 Token**。本项目适配形态：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_TOKEN}"
      }
    }
  }
}
```

**5. 源代码** — 形式不限，但须真实使用麦当劳 MCP 能力（见下）。

## 三、仓库级硬性要求（非文件，但同样卡报名）

1. **GitHub 仓库必须 Public 且保持公开可访问**（报名后至活动结束）。
2. **项目创建时间**：北京时间 2025-12-25 00:00 — 2026-10-25 23:59（麦当劳 MCP 上线日起算）。
3. **须真实使用麦当劳 MCP 能力**；如领 WorkBuddy 奖励，还须真实使用腾讯 WorkBuddy。
4. **安全红线（参赛声明 + 规则双重约束）**：项目及提交材料中**不得包含真实 Token、密钥、密码、账号凭证、他人个人信息**；配置文件仅使用环境变量占位符。违规可直接取消资格。
5. **内容合规**：不得出现违法违规、敏感、贬低麦当劳品牌、与其他品牌对比、恶意代码/外链等内容。
6. **原创性**：项目须为原创或已取得合法授权。
7. **同一账号多项目只取 Star 最高者进榜**；Star 数为 0 不进榜；前 100 名进榜（含并列）。
